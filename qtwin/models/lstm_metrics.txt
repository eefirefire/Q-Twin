Week 3 Task 3 -- Stage 2a Sequence Model (LSTM) Prototype
============================================================

SUPERSEDED (2026-09-12): the model files this document describes
(lstm_probe_stage.pt / lstm_config.json) have been REPLACED by a
single-replicate-augmented retrain -- see lstm_augmented_metrics.txt for
the current official model. The numbers below (75.8% / 33-chip, 45.5% /
blind hold-out) are kept as the historical record of what motivated the
augmentation: the 45.5% hold-out number was traced to a diagnosed root
cause (this model's training data only ever contained 2-replicate-averaged
curves, never a genuine single-replicate noise profile) and fixed by
training on an expanded set that includes real single-replicate examples.
The current model reaches 72.7% on the same blind hold-out set (still
75.8% on the 33-chip set). This file's architecture/tuning description
below is otherwise still accurate background.

This model takes the full probe-stage curve shape (60-point resampled
sequence, 0-45s window) rather than the single early_displacement_30s
number the Task 1 gatekeeper used. DIVERGENT_REPLICATES rows are NOT
feature-blanked the way they are for the gatekeeper -- this model sees
the genuine average-of-two-replicates curve (including the corrupted
flat/spike replicate baked into that average) and has to learn to
recognize divergence from curve shape itself.

Architecture: single-layer LSTM -> dropout(0.2) -> linear(3-way softmax),
class-weighted CrossEntropyLoss (inverse class frequency -- added after the
Task 4 divergence fix shrank FAILURE to a training-set minority; matches the
gatekeeper's class_weight='balanced' approach).
Tuning iteration performed: hidden_size in {16, 32, 64} x epochs in
{80, 150, 220}, selected via an internal 80/20 stratified split of the
synthetic training data (NOT the real validation set -- that split is only
used for architecture/epoch choice, never to pick hyperparameters by peeking
at real accuracy).

HONEST CAVEAT: 155 synthetic training curves and a 3-class problem is a
small dataset for a sequence model -- this is a feasibility prototype, not
a production classifier. Compare this accuracy against gatekeeper_metrics.txt
(Task 1's Random Forest on the same real validation chips) to see whether the
extra curve-shape information actually helps over the single-number biomarker,
or whether it just adds noise/variance for a dataset this size.

UPDATE after the Week 3 Task 4 replicate-divergence fix: this accuracy dropped
from an earlier 87.9% to 75.8%, and that's a real, understood trade-off, not a
regression to quietly work around. Making the synthetic data's divergence rate
match real chips (see Task4_Replicate_Divergence_Investigation.md) shrank
FAILURE to a training-set minority (13/155 rows) -- weak-signal/DEFECTIVE_CHIP
curves are the ones most prone to replicate sign-flips under the new jitter, so
they get swept into DIVERGENT_REPLICATES disproportionately. Class-weighted loss
plus the epoch-extended tuning above recovered most of the gap (51.5% -> 69.7% ->
75.8% across three fix attempts, each kept and documented rather than only the
final number shown). The gatekeeper (Task 1) held at 100% through the same data
change because it isn't blanking early_displacement_30s on divergence anymore
either (see that model's own updated docstring) -- it still has a near-perfect
continuous feature to lean on. This model has to read curve SHAPE for a class
that's now genuinely under-represented, which is a harder problem, honestly
reflected in a lower number rather than hidden behind further tuning.
