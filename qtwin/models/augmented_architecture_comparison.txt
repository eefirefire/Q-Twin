Augmented architecture comparison: LSTM vs. LSTM+Attention vs. TCN,
all trained on the single-replicate-augmented (310-sequence) training set
==============================================================================

Closes two previously-separate open items:
1. lstm_tcn_comparison.py flagged LSTM+Attention/TCN as beating the plain
   LSTM (87.9% vs 75.8%) but never promoted them, and never trained them on
   the single-replicate-augmented data (that fix came later).
2. Known_Limitations_Master.md flagged that neither architecture had been
   re-compared against the augmented LSTM baseline, or evaluated on the
   blind hold-out set AT ALL -- this is the first time either has been.

33-chip accuracy = 0.758, hold-out accuracy = 0.727
(lstm_augmented_metrics.txt) -- the baseline every architecture below is
compared against.

HONEST INTERPRETATION:
Best hold-out accuracy: LSTM (baseline) (0.727) vs. currently-promoted LSTM's 0.727.
Best 33-chip accuracy: LSTM (baseline) (0.788) vs. currently-promoted LSTM's 0.758.

NOTE on the 'LSTM (baseline)' row: this is NOT a different trained model
from the officially-promoted one in lstm_augmented_metrics.txt -- same
architecture, same training set, same tuning discipline, just a different
RNG seed (this script reruns its own independent sweep so all three
architectures are trained under identical conditions here, same practice
as lstm_tcn_comparison.py). Its 33-chip number differing from the official
0.758 (here: see summary above) is run-to-run noise at this dataset size,
not a second, better LSTM to consider promoting.

No architecture beats the currently-promoted augmented LSTM on hold-out
by a margin large enough to justify a promotion, given this hold-out set's
small n=11 (each chip is ~9% of the reported accuracy) -- a real, honest
null result, not forced into a positive finding.

n=11 hold-out and n=33 real validation are both small -- treat every
number here as having real sampling noise, especially any single-chip
swing on the hold-out set. HONEST METHODOLOGY NOTE (same as
model_trainer_augmented.py / lstm_augmented_metrics.txt): reporting
hold-out numbers as part of an architecture-selection decision means this
hold-out set is no longer fully untouched by downstream choices.
