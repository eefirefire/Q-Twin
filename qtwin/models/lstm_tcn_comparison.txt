Week 4 Task 4 -- LSTM tuning beyond the first pass: LSTM vs. LSTM+Attention vs. TCN
======================================================================

HONEST NOTE ON SCOPE: the Week 4 plan named the target weak point as
'DIVERGENT_REPLICATES: 4/7 misclassified as SUCCESS' -- that describes the
PRE-Task-4-fix LSTM (87.9% run, Week 3). The Week 3 follow-up session already
changed this: the current baseline (lstm_metrics.txt, 75.8%) has
DIVERGENT_REPLICATES recall = 1.00 (all 7 caught) but precision = 0.47 (it
over-triggers -- 8 of 15 chips predicted DIVERGENT_REPLICATES are actually
SUCCESS/FAILURE). Targeting the plan's literal, now-stale weak point would
mean optimizing for a problem that no longer exists, so this comparison
targets the CURRENT real weak point instead: DIVERGENT_REPLICATES precision
and SUCCESS/FAILURE recall. Flagged as a deliberate deviation, not silent.

All three architectures tuned via the SAME internal 80/20 synthetic
tuning-split methodology (never selecting hyperparameters by peeking at real
validation accuracy), then evaluated once against the same 33 real
non-hold-out chips model_trainer.py uses.

RE: the 'LSTM (baseline)' row above scoring notably worse (0.727)
than the officially-saved Week 3/4 baseline in lstm_metrics.txt (0.758,
hidden_size=16, epochs=220): this is NOT the same trained model. This script
reruns its own independent internal-tuning-split sweep (different RNG seed than
model_trainer.py) purely so all three architectures in this comparison are
tuned/trained under identical conditions for a fair three-way comparison -- it
does not overwrite or supersede lstm_probe_stage.pt/lstm_metrics.txt, which
remain the official Task 3 deliverable. That said, the SIZE of the gap is itself
a real, honest finding: this dataset is small enough that which hyperparameters
an internal 80/20 split happens to prefer varies run-to-run more than would be
ideal, and real-validation accuracy is correspondingly noisy. Treat any single
LSTM run's exact number, including this comparison's, as having a real margin of
uncertainty -- the qualitative finding (attention and TCN both improve
DIVERGENT_precision substantially over an unweighted/unaugmented LSTM) is the
robust part, not any one decimal.

HONEST INTERPRETATION:
Best overall accuracy: LSTM+Attention (0.788).
Best DIVERGENT_REPLICATES precision (the current baseline's actual weak
point): LSTM+Attention (0.500, recall 1.000).
Compare each architecture's DIVERGENT_precision/recall and SUCCESS/FAILURE
recall above directly -- there is no single 'winner' metric here, since the
baseline's problem is a precision/recall trade-off, not a simple accuracy
gap. Whichever architecture raises DIVERGENT_precision without dropping
DIVERGENT_recall back down is the one worth carrying forward; if none do,
that itself is a real finding about this dataset's size (155 synthetic
curves, 13-91 rows per class) rather than an architecture-choice problem.

RECOMMENDATION (not yet acted on): both LSTM+Attention and TCN clearly beat
the officially-saved LSTM baseline on every tracked metric (accuracy,
DIVERGENT_precision, SUCCESS_recall, FAILURE_recall) in this comparison.
LSTM+Attention is the more natural promotion candidate -- same recurrent
family as the existing Task 3 deliverable, just replacing last-hidden-state
pooling with learned attention over the 60 timesteps, so the change is easy
to explain and audit. Deliberately NOT swapping this into
lstm_probe_stage.pt/lstm_config.json/the Streamlit mockup in this pass:
promoting a different architecture to 'the' Stage 2a model is a real
decision (same category as the Task 4 divergence fix), not a documentation
task, so it's flagged here for explicit sign-off rather than done
unilaterally alongside a comparison report.
