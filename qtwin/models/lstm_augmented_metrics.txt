LSTM improvement: single-replicate data augmentation
============================================================

SUPERSEDED (2026-09-12): the "improvement" this file documents did not
survive a determinism-bug fix. torch.manual_seed() alone does not make
CPU-trained PyTorch models bit-reproducible; every torch training script
in this project (including this one) only had that, not
torch.set_num_threads(1) + torch.use_deterministic_algorithms(True).
Under the fix, regenerating this exact model gives 0.576 / 33-chip (was
0.758) and 0.545 / hold-out (was 0.727) -- i.e. ZERO real hold-out
improvement over the pre-augmentation baseline (also 0.545 under the
fix) and an actual REGRESSION in 33-chip accuracy. The 45.5%->72.7%
headline result below was a thread-scheduling artifact, not a real
effect of the augmentation technique. This file briefly caused the
augmented plain LSTM to be promoted to official, and a "keep it
official" instruction to be given in conversation, before the bug was
caught -- both retracted. TCN (also trained on the augmented set) is now
the official model -- see tcn_official_metrics.txt. Kept as historical
record of the (incorrect) original claim and the reasoning that produced
it, per this project's standing practice of not deleting superseded
results. Full corrected account: Known_Limitations_Master.md's Stage 2a
determinism section.

Technique: added 155 single-replicate synthetic training sequences
(augment_single_replicate_data.py) alongside the original 155
two-replicate-averaged ones, directly targeting the diagnosed root
cause of the LSTM's weak SINGLE_REPLICATE performance (56.25% on that
subclass in the 33-chip validation set) -- the original training data
only ever contained averaged-2-replicate curves, so the model had never
seen genuine single-replicate noise statistics.

Training set: 310 sequences (310 = 155 original + 155 augmentation).
Tuning: same hidden_size x epochs grid, same internal 80/20 synthetic
split discipline as model_trainer.py -- never selecting hyperparameters
by peeking at real validation accuracy.
  hidden_size= 16 epochs= 80: internal tuning-split accuracy = 0.661
  hidden_size= 16 epochs=150: internal tuning-split accuracy = 0.677
  hidden_size= 16 epochs=220: internal tuning-split accuracy = 0.677
  hidden_size= 32 epochs= 80: internal tuning-split accuracy = 0.694
  hidden_size= 32 epochs=150: internal tuning-split accuracy = 0.645
  hidden_size= 32 epochs=220: internal tuning-split accuracy = 0.677

  hidden_size= 64 epochs=220: internal tuning-split accuracy = 0.694

HONEST METHODOLOGY NOTE: the root-cause diagnosis (SINGLE_REPLICATE
weakness) was visible in the 33-chip validation set on its own (56.25%
there), independent of hold-out results -- so this fix isn't reverse-
engineered from hold-out chip identities. That said, reporting hold-out
numbers here means this hold-out set can no longer be treated as fully
untouched by any downstream modeling decision the way it was before this
change -- flagged plainly, not glossed over. A cleaner future test would
need a second, still-untouched hold-out set to confirm this generalizes.
